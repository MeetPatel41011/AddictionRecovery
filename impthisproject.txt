3.1  REINFORCEMENT LEARNING (Contextual Bandit Model)
-----------------------------------------------------
  File: rl_bandit.py

  WHAT IT DOES:
    The AI uses a Contextual Bandit algorithm (a type of Reinforcement Learning)
    to recommend daily recovery tasks personalized to each user. It considers:
      - Current mood (1-5 scale)
      - Current urge level (0-10 scale)
      - Current streak (days of continuous recovery)
      - Addiction type (alcohol, opioids, gambling, etc.)

  HOW IT LEARNS:
    Every time a user completes a task, the system records the OUTCOME:
      - Was the task completed? (yes/no)
      - What was the urge BEFORE the task?
      - What was the urge AFTER the task?
      - What was the user's mood?
      - What was their streak?

    The RL model calculates a REWARD based on urge reduction:
      reward = (urge_before - urge_after) / 10.0

    This reward updates the Q-table (a state-action value table) using:
      Q(state, action) += alpha * (reward - Q(state, action))

    Over time, the model learns which tasks work best for specific
    user states (e.g., "when urge is high and mood is low, recommend
    breathing exercises rather than journaling").

  KEY AI FEATURES:
    a) Epsilon-Greedy Exploration (epsilon = 0.2)
       - 80% of the time: recommends the best-known task
       - 20% of the time: explores random tasks to discover new winners

    b) Cross-User Aggregate Learning
       - When a NEW user starts, the model checks the database for
         historical performance data from ALL past users
       - This "warm-starts" the new user's recommendations using the
         best tasks discovered across the entire population

    c) Priority Weighting for Clinician Tasks
       - Tasks prescribed by clinicians get a 2.0x priority weight
       - This means clinician-prescribed tasks are preferred when
         their Q-value is similar to general tasks

    d) Contextual State Space
       - State = (mood_bucket, urge_bucket, streak_bucket)
       - Mood: low (1-2), mid (3), high (4-5)
       - Urge: low (0-3), mid (4-6), high (7-10)
       - Streak: new (0-2), building (3-13), strong (14+)

  WHERE AI DATA IS STORED:
    - Q-table: In-memory on the server (resets on restart, warm-started
      from database on next boot)
    - Task outcomes: PostgreSQL database (table: task_outcomes)
      This is PERMANENT and survives server restarts.
    - The static output.json is NEVER modified by the AI.

  HOW TO TEST:
    > curl "http://localhost:8000/get-tasks?mood=3&urge=7&streak=2&addiction_type=alcohol"
    
    This returns 3 AI-recommended tasks. Run it multiple times with
    different parameters to see how recommendations change.

    Complete a task to train the model:
    > curl -X POST http://localhost:8000/complete-task ^
        -H "Content-Type: application/json" ^
        -d "{\"task_id\":\"gen_42\",\"completed\":true,\"prev_urge\":7,\"next_urge\":3,\"mood\":3,\"streak\":2}"

    Check AI learning progress:
    > curl http://localhost:8000/ai-learning-log


3.2  TASK MERGING SYSTEM
-----------------------------------------------------
  File: task_merger.py

  WHAT IT DOES:
    For premium (facility-linked) users, this module merges two task pools:
      1. General tasks from output.json (1195 clinical recovery tasks)
      2. Clinician-prescribed tasks from PostgreSQL

    Merging rules:
      - Clinician tasks get source='clinician' and 2x priority weight
      - "avoid" tasks are separated from "do" tasks
      - If a clinician task overlaps with a general task trigger, clinician wins

  HOW TO TEST:
    Upload clinician tasks via the Facility Portal (Treatment tab), then
    request tasks for that patient — you should see clinician tasks
    appear with higher priority.


3.3  RAG PIPELINE (Clinical Knowledge Retrieval)
-----------------------------------------------------
  File: rag_pipeline.py

  WHAT IT DOES:
    Uses ChromaDB vector database with sentence embeddings to perform
    semantic search over the clinical knowledge base extracted from:
      - NIDA Principles of Drug Addiction Treatment
      - SAMHSA TIP 34 Brief Interventions
      - ASAM Multidimensional Assessment Guide

    When the AI coach or report generator needs clinical context,
    it queries this vector store for relevant passages.


3.4  PDF PARSING & KNOWLEDGE EXTRACTION
-----------------------------------------------------
  File: pipeline.py

  WHAT IT DOES:
    Ingests clinical PDF documents, chunks them semantically (preserving
    clinical "If/Then" logic and interventions), uses an LLM to extract
    structured data, and outputs the finalized output.json knowledge base.


3.5  AI LEARNING LOG (Intelligence Report)
-----------------------------------------------------
  File: ai_learning_log.py

  WHAT IT DOES:
    Generates a comprehensive JSON report showing exactly what the AI
    has learned from user interactions. Includes:
      - Total learning events (how many task completions recorded)
      - Per-addiction analysis (which addiction types have most data)
      - Clinician vs General task comparison (which source performs better)
      - Top/bottom performing tasks (best and worst by reward)
      - Warm-start readiness (can new users benefit from past data?)
      - Recent learning events (last 50 interactions with rewards)

  HOW TO TEST:
    Browser:  http://localhost:8000/ai-learning-log
    Terminal: curl http://localhost:8000/ai-learning-log

    Also generates a local file: ai_learning_log.json


3.6  AI-POWERED COACH (Claude Integration)
-----------------------------------------------------
  File: recovery-compass.html (frontend JavaScript)

  WHAT IT DOES:
    An in-app AI chatbot powered by Claude (Anthropic API) that acts as
    a recovery coach. It:
      - Uses the patient's actual check-in data, journal entries, and
        streak to make responses deeply personal
      - Follows strict clinical safety guidelines (never diagnoses,
        never recommends medications, always defers to providers)
      - 5 sessions per day limit
      - Quick prompt buttons for common situations

  HOW TO TEST:
    Go to the Coach tab in the patient dashboard and send a message.
    Try: "I'm having strong cravings right now" or "Help me with stress"


3.7  AI-GENERATED REPORTS
-----------------------------------------------------
  File: recovery-compass.html (frontend JavaScript)

  WHAT IT DOES:
    - PATIENT: Generates personalized progress reports with sections on
      Progress Summary, What's Working, Areas to Watch, This Week's Focus
    - FACILITY: Generates formal clinical progress reports suitable for
      patient charts with Clinical Summary, Risk Factors, Recommendations

  HOW TO TEST:

6. SECURITY & AUTHENTICATION
================================================================================

6.1  OTP VERIFICATION & AUTHENTICATION
  - Patient Login: Uses explicit Username and Password created during onboarding.
  - Facility Login: Uses explicit Access Code and Password created during registration.
  - New Patient Signup: 4-digit OTP code generated at the end of onboarding for extra verification.
  - Displayed via alert() (development mode — production would use
    SMTP/SMS provider)
  - Sleek 4-digit input overlay with:
    - Auto-advance on digit entry
    - Backspace support
    - Paste support (for full 4-digit paste)
    - Error animation (shake) on wrong code
    - Success animation (green highlight) on correct code
    - Resend OTP button

6.2  FACILITY APPROVAL WORKFLOW
  - Users who signup with a facility code get status = "pending"
  - Pending users see a "Waiting for Facility Approval" screen
  - Screen auto-polls server every 10 seconds for status update
  - Once approved, auto-redirects to patient dashboard
  - If rejected, shows rejection message

6.3  CLIENT DATA ISOLATION
  - Premium client data stored in isolated directories:
    client data/{client_id}/
  - Each clinical update creates a timestamped JSON audit file
  - Free-tier users have NO clinical data footprint
  - GDPR-compliant data erasure endpoint available

6.4  DATABASE SECURITY
  - PostgreSQL on Neon (cloud-hosted, SSL-encrypted)
  - Environment variables for sensitive credentials
  - No plaintext passwords in code

================================================================================
9. DATABASE & DATA FLOW
================================================================================

  PostgreSQL Tables (Neon Cloud):
  ───────────────────────────────
  users           — User profiles (id, name, age, dob, addictions, status, etc.)
  task_outcomes    — Every task completion/skip with reward data (AI learning)
  clinician_tasks — Clinician-prescribed tasks for premium users

  Data Flow:
  ───────────────────────────────
  1. User signs up → POST /user/create → user saved to PostgreSQL
  2. User requests tasks → GET /get-tasks → RL model selects from merged pool
  3. User completes task → POST /complete-task → outcome saved to PostgreSQL
     → RL model's Q-table updated → AI gets smarter
  4. New user joins → RL model warm-starts from aggregate historical data
  5. Clinician uploads tasks → saved to PostgreSQL → merged into task pool
  6. External scheduler POSTs → saved to PostgreSQL + audit JSON file
  7. AI learning log queried → reads all task_outcomes → generates report

  Static Data (NEVER modified by AI):
  ───────────────────────────────
  output.json — The master clinical knowledge base (1195 tasks)
  This file is READ-ONLY. The AI never writes to it.
  All AI learning is stored in PostgreSQL (task_outcomes table).

  File-Based Audit (Premium Only):
  ───────────────────────────────
  client data/{user_id}/  — Per-client isolated directory
  Each update creates: {user_id}_{timestamp}.json
  Contains: clinical notes, task schedules, audit metadata
  Free-tier users have NO folder here.
